# BE 프로젝트 초기 구조

언어, 프레임워크, DB, 인증과 PG 공급자를 정할 때 아래 모듈 경계를 해당 프레임워크의 관례에 매핑한다. 현재 저장소에는 FE와 같이 리뷰할 [API 계약](API_CONTRACT.md)과 공통 응답 예시가 있다.

```text
Back/
  docs/
    API_CONTRACT.md
    PROJECT_SETUP.md
  contracts/
    examples/
      product-list.json
      validation-error.json
```

| 초기화 이후 모듈 | 책임과 병합 경계 |
| --- | --- |
| 앱과 공통 설정 | 앱 진입점, 서버 주소, CORS, 환경별 설정, DB 연결 |
| 공통 HTTP | API 버전 경로, 입력 검증, 인증·인가 진입점, 오류 변환, 요청 ID |
| 사용자와 동네 | 인증 세션, 프로필, 동네 확인, 정책 버전과 동의 기록 |
| 제품과 카테고리 | 검색·예산 필터·등록, 트랙별 입력과 품목 정책 |
| 거래 | 참여자 권한, 상태 전이, 기한, 문고리 정보, 후기 |
| 결제 | 결제수단 등록 연동, 보류·해제·정산, 중복 이벤트 처리 |
| 파일과 채팅 | 업로드 목적과 사용 권한, 거래 채팅 접근 권한 |
| DB 마이그레이션 | 프로젝트에서 채택한 도구의 경로에 버전별 변경을 기록 |

## 초기 PR에서 정할 항목

- 런타임과 빌드 도구 버전, DB, 로컬 실행·검사 명령과 마이그레이션 방식
- 서버 포트, DB 연결, FE 허용 출처, 인증, 파일 저장소와 PG 설정에 사용할 환경 변수 이름. 로컬·테스트용 예시는 값의 형식만 제공한다.
- 공유 HTTP 오류 구조와 날짜·금액 직렬화 기준. 첫 기능 PR에서 `contracts/examples/`와 응답이 일치하는지 확인한다.

## 연동 순서

1. 제품 목록·상세의 필드와 빈 목록을 FE와 먼저 맞춘다. 카테고리와 동네 범위에 의존하는 테스트 데이터를 정한다.
2. 거래 상태 전이와 참여자 접근 테스트를 만든다. 주소 공개, 사진 접근, 유효하지 않은 상태 전이, 요청 재시도 시의 결과를 확인한다.
3. PG 테스트 환경이 준비되면 보류 성공·실패, 중복 알림, 해제와 정산을 실제 결과로 검증한다. 결제·품목·분쟁 정책은 적용 기준을 확정한 뒤 서비스에 연결한다.
